# 故障诊断：先定位层级，再最小修复

诊断默认只读。用户说“检查、看看、为什么”不等于授权重启、升级、切 target、轮换 IP、重装或改防火墙。不要把“最常见”当成“已经证实”。

## 先记录故障边界

优先从现有上下文和只读证据取得信息；仍缺失时最多集中问三个能改变判断的问题：

1. 哪个实际客户端、版本和网络出现问题；是否所有用户、所有网络都失败。
2. 错误原文和首次发生时间；此前最后一次成功及最近变更。
3. 直连 VLESS、订阅、面板中哪一条路径失败；不要要求用户公开粘贴完整私密 URL。

记录检查时刻和时区。间歇性问题要对齐服务日志、云平台事件、客户端失败时间和计量窗口。

## 最小证据包

按故障范围选择，不要无目的收集全部日志：

- 对象：实例、供应商/区域、公网或 NAT、系统/架构、入口与控制面模式。
- 主机：uptime、时间同步、磁盘/内存、失败服务、OOM/重启历史。
- 进程与配置：x-ui/Xray 状态、实际监听进程、core `run -test`、面板 API 读回。
- 网络：云防火墙、主机防火墙、NAT/LB 映射、IPv4/IPv6、从目标外部网络的 TCP 可达。
- REALITY：服务端地址和公共端口、当前 SNI/target 是否一致、临时客户端握手与出口；敏感字段只比对 match/mismatch。
- 控制面：回环监听、Tunnel/SSH/公网路径、完整订阅响应类型与解析结果，不能只看 HTTP 200。
- 变更：最近安装、升级、target/端口/防火墙/订阅变更及对应备份。

日志只取故障窗口附近并脱敏。不要输出环境文件、完整链接、请求头、数据库或私密配置。

## 症状路由

| 现象 | 先查 | 常见层级 | 在确认前不要做 |
|---|---|---|---|
| 所有人所有网络都超时 | 实例运行、PUBLIC_PORT 外部 TCP、云/NAT/主机规则、监听 | 云网络或主机入口 | 换 SNI、重装面板 |
| 只有一个用户失败 | 启用状态、UUID/Sub ID、额度/到期、该用户订阅内容 | 用户凭据或客户端 | 重建公共入站、影响其他用户 |
| Wi-Fi 可用、蜂窝失败 | 同一配置在两网实测、运营商可达、IPv4/IPv6、地区限制 | 客户网络 | 断言服务端坏了或盲换 target |
| TCP 可达但 REALITY 握手失败 | 当前 SNI/公钥/Short ID/flow、服务端配置测试、target TLS | REALITY 参数或 target | 连续轮换多个 SNI |
| 显示已连接但无互联网 | 临时代理实际出口、Xray outbound/routing、DNS、额度 | 出站、路由或 DNS | 只凭客户端“已连接”判成功 |
| 订阅 200 但导入/连接失败 | Content-Type/body 是否为配置、字段与真实入站是否一致、客户端内核兼容 | 订阅生成或客户端 | 把 200 当验收完成 |
| 订阅 404 | 完整随机路径/Sub ID、Tunnel Host、服务监听；区分根路径 404 | 控制面路径 | 重装 3x-ui |
| 面板进不去 | 模式、SSH forward/Tunnel Access、随机 Web Base Path、回环监听 | 控制面 | 临时开放公网面板 |
| 切 target 后 reset/EOF | 服务端与所有订阅 SNI 是否同步、任务是否真正结束、旧缓存 | 变更不同步 | 用旧测试记录判断新配置 |
| 供应商流量高于面板 | 同一时间窗的整机、认证用户、Tunnel 和回落统计 | 计量口径或未认证回落 | 直接断言“偷流量”或靠用户额度兜底 |
| SSH 拒绝 | 实例/端口/用户/密钥指纹、云规则、控制台 | 管理入口 | 开密码登录、删除所有公钥 |

客户端侧的导入方式、格式选择和常见报错见 [客户端导入与验收](clients.md)。

## 判断与修复门槛

先输出一个诊断结论：`已定位 / 高概率 / 证据不足 / 多故障并存`，并列出支持证据和反证。证据不足时给下一项最小只读检查，不用一串可能原因淹没用户。

获得修复授权后：

1. 保存故障现场和一致性备份，写明将改变的唯一主要变量。
2. 能使用随附 helper 就使用；现场 schema 不匹配时停止适配，不直接改活跃数据库。
3. 应用一个最小修复。服务重启、target 切换、用户轮换、规则变更不得捆成一次试错。
4. 重跑受影响层以及所有下游层。例如修 SNI 后还要验证订阅同步、真实握手和出口；修 Tunnel 后不能据此宣称 REALITY 已恢复。
5. 无改善就回到证据阶段；不要连续重启、换 target、换端口和升级。回退须在本次授权范围内并重新验证旧状态。

## 结束条件

- 修复成功：原始症状在原客户端和原网络消失，并完成对应分层验收。
- 部分恢复：明确哪些路径已恢复、哪些用户/网络仍失败。
- 状态未知：外部网络、云控制台或真实客户端证据缺失；不能写“服务器正常”。
- 阻塞：需要用户选择、外部账号权限、维护窗口或有风险的新授权。

最终只给一个优先下一步。多个独立问题可以分项，但不要把未经执行的建议写成已完成。
