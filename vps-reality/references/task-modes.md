# 任务模式与交互

本页让用户可以用普通话提出目标，Skill 负责转换为安全、可验证的工作流。不要要求用户先选择协议字段、背命令或理解面板 schema。

## 共同入口

先从现有上下文和只读检查确认目标主机、授权范围及当前状态。多台实例、相似 SSH 别名或旧 checkout 无法消歧时，只问一个对象定位问题并停止写操作。

对话规则：

- 能检查得到的系统、架构、监听、版本和已有服务不再询问。
- 部署场景在只读盘点后集中询问缺失输入，并让用户明确选择控制面；不要拆成许多零散确认。
- 诊断场景先做获准的只读检查，再问最多三个能改变判断的问题，例如实际客户端、错误原文、是否只在某个网络失败。
- 已授权、风险未变化的连续步骤不逐项打断；出现新中断、凭据处理、外部账号授权、公开暴露或不可逆操作时再停下说明。

## `audit`：只读检查

适用表达：检查一下、健康检查、现在安全吗、是否正常、不要修改。

1. 运行 `preflight.sh`，结合云控制台和 [分层验收](verification.md) 收集现状。
2. 不重启、不更新、不切 target、不开放端口、不安装监控。
3. 把每一项标为 `通过 / 失败 / 未验证 / 不适用`，不能把缺证据写成正常。
4. 输出当前可用性、暴露面、最重要的问题和一个优先建议；修复须另获授权。

## `deploy`：新装或迁移

适用表达：从零搭建、新 VPS、迁移节点、帮我装好。

1. 先按平台、网络和已有业务做只读盘点。
2. 告知支持结论；只补齐缺失的入口、控制面、用户/额度、实际客户端和恢复入口。
3. 一次给出变更摘要、中断、凭据位置、备份与回滚点。重装系统等不可逆动作另行最终确认。
4. 使用 [完整部署流程](deploy.md)，按 [分层验收](verification.md) 交付。安装结束不等于完成。

## `user-change`：用户、额度和泄漏处置

适用表达：加用户、删用户、改流量、改到期、某人的链接泄漏了。

1. 精确解析目标用户；同名或多个匹配时停止写入。
2. API 读回当前入站和客户清单，做一致性备份；新增时生成独立 UUID 与 Sub ID。
3. 只修改该用户及必要订阅映射，不重建入站、不重跑安装。
4. 写后验证 API 读回、用户隔离、订阅解析、REALITY 握手和额度/到期。删除或停用后还要验证旧订阅不可用。
5. 泄漏处置必须轮换受影响 UUID 与 Sub ID；只换 URL 外观不算完成。

## `diagnose`：按症状定位

适用表达：连不上、超时、EOF、断流、能连但打不开网页、订阅 404、面板进不去、流量异常。

1. 阅读 [故障诊断](troubleshooting.md)，先判断故障层，不先猜 SNI 或重启服务。
2. 收集最小证据包并给出根因置信度；把事实与推断分开。
3. 未获修复授权时只给建议。获授权后只做一个最小修复，再重跑受影响层和下游验收。
4. 修复失败时保留现场，不连环尝试多个高影响动作。

## `maintenance`：升级、target 切换和恢复

适用表达：升级 3x-ui/Xray、换 SNI/target、回滚、恢复备份。

1. 读取 [版本与官方资料](sources.md) 与 [运维和回滚](operations.md)。升级或 target 切换都不是健康检查的默认补救。
2. 固定准确版本，确认维护窗口、并发写入、回退对象和中断范围。
3. 一次只改变一个主要变量；不要同时升级系统、面板、core 和 target。
4. 失败或超时先读回事实。只有回退已在授权范围内且目标备份已核验时才恢复。

## 输出契约

第一行必须是以下之一：

```text
完成：用户现在可以……
部分完成：……已可用；……尚未验证。
阻塞：缺少……，继续会有……风险。
状态未知：检查未取得……证据，不能判断为正常或失败。
```

后续只保留与本次模式有关的内容：目标与平台、已执行变更、验证证据、未验证项、凭据私密位置、回滚点和下一步。不要粘贴完整订阅、UUID、Sub ID、私钥、Token、随机面板路径或密码。
